# 0.6 Nouvelle note dans la version SPA

L'utilisateur écrit une note dans le formulaire de `/spa` et clique sur **send**.
Le formulaire n'ayant pas d'attribut `action`, c'est le gestionnaire d'événement `onsubmit`
de `spa.js` qui prend la main.

```mermaid
sequenceDiagram
    participant browser as Navigateur
    participant server as Serveur (Express)

    Note over browser: L'utilisateur saisit le texte puis clique sur "send"<br/>Déclenchement de l'événement submit

    browser->>browser: form.onsubmit s'exécute : e.preventDefault()<br/>→ la soumission classique est annulée, aucune navigation
    browser->>browser: note = { content: e.target.elements[0].value, date: new Date() }<br/>notes.push(note) — mise à jour locale
    browser->>browser: redrawNotes() réécrit le <ul> via le DOM<br/>et le champ de saisie est vidé<br/>→ l'utilisateur voit sa note immédiatement
    browser->>browser: sendToServer(note) :<br/>xhttpForPost.open('POST', '/new_note_spa', true)<br/>setRequestHeader('Content-Type', 'application/json')<br/>send(JSON.stringify(note))

    browser->>server: POST /new_note_spa<br/>Content-Type: application/json<br/>corps : { "content": "...", "date": "2019-05-25T15:15:59.905Z" }
    activate server
    Note right of server: Le serveur ne peut lire le corps que grâce<br/>à l'en-tête Content-Type (Express + body-parser/json)
    server-->>browser: 201 Created + la note créée en JSON
    deactivate server

    Note right of browser: Aucune redirection, aucun rechargement :<br/>la page n'est pas rechargée, le DOM reste intact
```

**Total : 1 seule requête HTTP.** C'est toute la différence avec l'exercice 0.4 :
la note apparaît à l'écran *avant* d'être confirmée par le serveur, et le serveur répond `201`
au lieu d'une redirection `302`.
